# Что должна делать программа

Нужно упростить проверку тактильного модуля. Вместо ручного сравнения частот программа читает таблицу и проверяет результат по допуску.

## Первая версия

На вход подается CSV с данными одного изделия. В каждой строке есть номер изделия, частота в герцах и амплитуда ускорения в м/с**2. Для всех точек напряжение возбуждения должно быть одинаковым.

Программа выбирает частоту с самым большим ускорением. Затем сравнивает ее с допуском из файла configs/calibration_limits.json. Сейчас там задано 170 +- 10 Гц, то есть от 160 до 180 Гц включительно. Пока что это учебные значения, а не требования к настоящему изделию.

Результат сохраняется в JSON: номер изделия, частота максимума, границы допуска и статус «Годен» или «Не годен». Статус относится только для проверки частоты.

## Что нужно проверить во входных данных

- В файле есть хотя бы три точки.
- Все строки относятся к одному изделию.
- Частоты положительные и не повторяются.
- Амплитуды неотрицательные. 
- Максимум один и находится не на краю диапазона.

Если данные не подходят, программа выводит причину ошибки. В таком случае старый result.json может остаться от предыдущего запуска, поэтому нужно смотреть сообщение в терминале.

## Ограничения

В examples/measurements.csv записаны придуманные данные для проверки кода. Программа пока не получает сигнал с датчика, не выполняет БПФ и не записывает настройки в устройство. Она работает с готовыми амплитудами. Частота максимума определяется только среди точек таблицы. Это еще не точное измерение механического резонанса и не полный выходной контроль изделия.
